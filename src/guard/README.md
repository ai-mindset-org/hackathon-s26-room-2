# guard — проверка черновика на выдумку и регламент

Модуль участника **QE2K**. Отвечает на два вопроса заказчика:
**«откуда цифры?»** и **«не выдумал ли он?»**

Только стандартная библиотека Python — ставить нечего.

## Зачем

Черновик, который выглядит уверенно и содержит выдуманную цену, хуже, чем
отсутствие черновика: человек его отправит. `guard` ставится последним звеном
конвейера и не пропускает такой текст к человеку.

```
запрос + база → [retrieve] → [pricing] → [draft] → ★ guard ★ → человек правит и отправляет
```

## Как использовать из другого модуля

```python
from src.guard import check

verdict = check(draft_text, "examples/base", request=request_text)

verdict.ok        # False → показывать человеку нельзя
verdict.errors    # список нарушений
verdict.claims    # каждый факт черновика с источником
verdict.to_dict() # то же в JSON
```

`request` необязателен, но без него нельзя проверить обращение по имени и
количества — передавайте, если он есть.

## Как запустить руками

```bash
python -m src.guard.cli src/guard/fixtures/good-02.md --example examples/02-запрос-кп
python -m src.guard.cli черновик.md --base examples/base --json
```

Код возврата: `0` — черновик опирается на базу, `1` — есть ошибки. Годится
как гейт в приёмке.

## Что проверяется

**Выдумка.** Каждое число, артикул, адрес и ссылка черновика должны иметь
источник: буквально в `base/`, из запроса клиента или из расчёта по прайсу.
Расчёт проверяется по-настоящему: `378 324` обосновывается как
`12 × 33 900 (TS-192E) − 7%`, а `485 266` — как сумма трёх строк. Поэтому
корректное КП проходит, а выдуманная цена — нет.

**Регламент** (`base/регламент-ответов.md`):

| Пункт | Проверка | Уровень |
|---|---|---|
| п.1 | обращение на «вы», имя клиента, без канцелярита | ошибка / внимание |
| п.2 | контакт поддержки — после шагов решения, а не вместо | внимание |
| п.3 | цена из прайса названа вместе с артикулом | ошибка |
| п.4 | никаких «завтра», сроки только из прайса | ошибка |
| п.5 | вопрос вне базы — честно сказано + передан менеджеру | ошибка |
| п.6 | подпись «Команда ТехноСклад» | ошибка |

Плюс условия прайса: скидка 7% не должна применяться к позиции меньше 10 шт
(ключевая проверка примера `02-запрос-кп`).

## Чего guard намеренно НЕ делает

- **не считает КП** — это `pricing`; guard только проверяет, что посчитанное
  выводится из базы;
- **не пишет текст** — это `draft`;
- не ловит пропущенную скидку там, где она положена: guard проверяет, что
  сказанное обосновано, а не что сказано всё, что можно.

## Тесты

```bash
python -m unittest src.guard.tests.test_guard -v
```

19 тестов, включая все три приёмочных примера в двух вариантах — чистый
черновик (должен пройти) и отравленный (должен быть пойман). Фикстуры лежат
в `src/guard/fixtures/`.

## Два бага, найденных тестами (для истории)

1. Число `6` из маркера списка «6. Подпись» в регламенте обосновывало
   выдуманные «ссылка живёт 6 часов». Разметка документа — не факт о мире.
2. Честный отказ «LTO-9 у нас нет» помечался как выдуманный артикул. Код,
   названный самим клиентом, черновик цитирует, а не выдумывает.
