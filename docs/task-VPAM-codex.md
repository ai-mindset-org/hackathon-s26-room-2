# Задача для Codex: Telegram-саппортер MVP (хакатон, 4 часа)

Построй рабочий MVP в папке `bot/` этого репозитория. Спека: `docs/interview-VPAM.md` — прочитай её.

## Что строим
Telegram-бот саппорта крипто-биржи. Клиент пишет боту в личку → бот отвечает по базе знаний без выдумок; если данных нет — эскалирует оператору.

## Жёсткие требования

1. **Python 3.9-совместимый код** (на машине python3 = 3.9). Зависимости — минимум: `requests` (или stdlib urllib). БЕЗ python-telegram-bot, БЕЗ numpy — чистый stdlib + requests. Long polling через Telegram Bot API (getUpdates).
2. **База знаний:** читается из пути в env `KB_PATH` (дефолт `/Users/agent/knowledge/BUILDIN_SELECTED_EXPORT_FINAL`). Индексер: пройти все `.md`, порезать на чанки по заголовкам (~120 строк макс), построить BM25-индекс в памяти при старте (простая реализация BM25 на stdlib, токенизация: lowercase + русские/латинские слова regex). Файлы `МАНИФЕСТ.csv`, `ОТЧЁТ_ОБЕЗЛИЧИВАНИЯ.md` — пропустить.
3. **LLM = локальная команда `codex exec`** (у владельца подписка ChatGPT, API-ключа НЕТ). Вызов: 
   `codex exec --skip-git-repo-check --sandbox read-only -m gpt-5.6-terra -o /tmp/out.txt "<prompt>"` 
   через subprocess, потом читать файл из `-o`. Таймаут 120с. Это работает — проверь одним вызовом.
4. **Диалоговая логика** (модуль `bot/brain.py`): на входящее сообщение — BM25-поиск топ-6 чанков по запросу (+ последние сообщения истории как контекст запроса), собрать промпт: системные правила + найденные чанки с путями файлов + история диалога этого пользователя (последние 20 сообщений) + новое сообщение. Модель должна вернуть JSON: `{"action": "answer"|"escalate", "reply": "текст клиенту", "reason": "почему"}`. Правила в промпте: отвечать только фактами из чанков; клиента звать по имени из Telegram-профиля; тон дружелюбный, короткий; если инфы в чанках нет или вопрос требует ручного вмешательства — action=escalate с вежливым сообщением клиенту, что вопрос передан оператору.
5. **История** (модуль `bot/store.py`): sqlite `bot/data/history.db`, таблица messages(user_id, username, first_name, role, text, ts). Изоляция по user_id. Переживает рестарт.
6. **Эскалация:** env `SUPPORT_CHAT_ID` — Telegram user id оператора. Бот шлёт туда: username/имя клиента, его вопрос, последние сообщения диалога, причину эскалации. Если SUPPORT_CHAT_ID не задан или отправка не удалась (оператор не нажал /start) — логировать эскалацию в `bot/data/escalations.log`, не падать.
7. **Картинки базы:** сделай отдельный скрипт `bot/describe_images.py`: идёт по всем png базы, для каждого зовёт `codex exec -i <png> ... "Опиши скриншот для индекса саппорта: что за экран, какие шаги/кнопки/поля видны"` и пишет `<папка>/images/image-NNN.caption.txt` рядом. Индексер подхватывает caption-файлы как чанки (источник = путь картинки + md-файл раздела). Скрипт НЕ запускай на все 149 картинок — это долго; запусти на 3 картинках для проверки, остальное владелец запустит фоном сам.
8. **Конфиг:** `.env` файл (bot/.env, читать простым парсером): TELEGRAM_TOKEN, SUPPORT_CHAT_ID, KB_PATH. Создай `bot/.env.example` с плейсхолдерами. Настоящий `.env` НЕ коммитить — добавь `bot/.env` и `bot/data/` в `.gitignore`.
9. **Запуск:** `python3 bot/main.py`. При старте: построить индекс (лог: сколько файлов/чанков), проверить getMe, лог «ready». Обработка /start (приветствие от саппорта биржи). Текстовые сообщения — в мозг. Нетекстовое — вежливо попросить текст.
10. **Тесты-смоук:** `bot/smoke_test.py` — без Telegram: строит индекс, задаёт 3 вопроса напрямую в brain (вопрос по базе / персонализация с фейковой историей / вопрос вне базы) и печатает JSON-решения. Прогони его, убедись что работает, покажи вывод.
